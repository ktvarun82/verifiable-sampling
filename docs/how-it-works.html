The problem

Why "just pick 10 at random" isn't good enough

When you press a button that does the random choosing on your own computer, an auditor a year later has no way to know you pressed it just once, honestly.

Spreadsheet and programming random functions (RAND(), Math.random()) all share one weakness: whoever runs them controls the starting point, so whoever runs them can quietly control the result. To a skeptical reviewer, "trust me, it was random" is not evidence.

Being genuinely honest isn't the issue — proving it is. This method replaces "trust me" with something a stranger can check for themselves, months later, without ever touching your computer.

Two ways a draw could be gamed

To be fair, the method has to close two doors

If you can see the random number before the list and the process are locked down, there are exactly two ways to cheat. The whole design exists to shut both.

Loophole 1 · Re-rolling

Draw again until you like it

If the random number already exists when you run the draw, you can simply run it over and over, keeping the one result that happens to pick the invoices you'd prefer nobody looks at.

✓ Closed by calling your shot early. You commit to a future beacon number — one that hasn't been created yet. You can't re-roll a dice that hasn't been thrown.
Loophole 2 · List-editing

Quietly change the list

If you can see the random number first, you can reorder or edit rows so the "random" pick lands where you want — swap a name here, delete a row there, and the outcome bends to you.

✓ Closed by sealing the list first. You publish a tamper-proof fingerprint of the exact list before the number exists. Change one character later and the fingerprint no longer matches.

The trick is old and simple: call your shot out loud, in public, before the dice leave your hand.

Everything below is just a careful, checkable version of that. Three ingredients make it work.

The three ingredients

What the fairness is built from

A sealed fingerprint of your list

A short code (a "hash") calculated from your exact list of 200 invoices. Change any single digit and the code changes completely.

Like a wax seal on an envelope: proof the contents haven't been swapped since it was closed.

A public number nobody controls

A worldwide beacon (drand) run jointly by many independent organisations publishes a fresh, unpredictable number every 3 seconds. No single party can fake it or foresee it.

Like the winning number on live national television: public, timed, and beyond any one person's reach.

A fixed recipe anyone can follow

A plain set of arithmetic steps that turns the sealed list plus the public number into the sample. No hidden randomness — same inputs always give the same 10 invoices.

Like a recipe card: follow it with the same ingredients and you bake the identical loaf, every time.

Under the hood

The recipe, in full

There is no secret sauce. It's three arithmetic steps — the same ones an auditor re-runs. Shown here for the curious; you don't need to read it to trust it.

The formula 
# 1. mix the public number with the sealed list
seed  = sha256( randomness + "|" + list_fingerprint )

# 2. give every invoice its own draw-ticket
ticket = sha256( seed + "|" + invoice_id )

# 3. sort by ticket, keep the first 10
sample = sort(all_invoices, by=ticket)[:10]
1

Mix. Blend the public beacon number with your list's sealed fingerprint into one shared starting seed. Both sides must be right, so neither can be tampered with.

2

Deal a ticket. Each invoice gets its own scrambled "lottery ticket" derived from that seed and its own ID — unpredictable, but fixed once the seed is known.

3

Sort & take ten. Line the invoices up by ticket and take the first ten. Every invoice had an equal chance; the outcome was sealed the moment the beacon spoke.

No language's random generator is used — so it reproduces identically in Python, JavaScript, or a shell one-liner.
